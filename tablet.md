# The Tablet — prosemirror-verbs

The founding principles of prosemirror-verbs. When code and a principle disagree, one of them is wrong and the disagreement is a finding, never routed around.

Every claim carries a mark: **settled** (decided, build on it), **pinned** (held, with a falsifiable test attached), or **open** (undecided, with its reason stated). Confident prose never closes an open question.

prosemirror-verbs began inside pm-testing-venue and inherits that venue's law. Where a ruling here amends one of the venue's stones, it says so; the venue's own tablet is parked, so those amendments are recorded to be carried up when it is carved.

## V1 — The verb-Schema · settled

ProseMirror registers the document's **nouns** — nodes and marks — in its `Schema`, declaratively, each with a spec. It leaves the **verbs** — commands — as bare functions, with no registry. This is that missing register: verbs, and how they are summoned, declared once as data. ProseMirror ships a noun-registry and no verb-registry; every serious editor rebuilds the missing layer, so the asymmetry is real and the name says the whole thing.

## V2 — Availability is a dry run · settled

A `Command` is `(state, dispatch?, view?) => boolean`, and it decides applicability before `dispatch` is consulted — so calling it without a dispatch is a free, side-effect-free question: "would this apply right now?". Availability needs no separate declaration; it falls out of the command. But *availability* and *activity* are two different questions: `toggleMark(strong)(state)` is true whether or not the mark is on, so the dry run says *enabled*, never *on*. Activity — is the mark lit — is a property of the selection and the document, carried by the verb's own readback, `read`. *(Amended 2026-07-19: the field here was originally `active`; the one-readback ruling dissolved it into `read` — see Vocabulary rulings.)*

## V3 — Verbs are declared or derived · settled

A verb enters the registry two ways. **Declared:** hand-written entries (`basicVerbs`), the way `prosemirror-schema-basic` ships a starter set. **Derived:** computed from the schema (`insertVerbs`), one *insert X* per node type, availability answered by ProseMirror's own `insertPoint` — the noun-equivalent of the command dry run. The verb-Schema does not merely sit beside the noun-Schema; it reads it and generates verbs from its content expressions. *Provenance: derivation was proven on the insert list, 2026-07-18 — availability is position-aware, and a node's required attributes become an arg-verb's arg-schema.*

## V4 — The API grants capabilities; a surface holds responsibilities · settled (2026-07-18)

The verb-Schema **grants capabilities** — pure, single-sourced computation of what is *possible* and *available*: the command dry run, insertability via `insertPoint`, derivations like `insertVerbs`. A **surface holds responsibility** — *curation* (which of the possible to show), presentation, interaction — consuming those capabilities plus its own conf. Logic is shared and single-sourced, so two surfaces can never disagree about what is possible; judgment and presentation are per-surface. This dissolves the possible-vs-desirable tension rather than answering it: **possible is the API's capability, desirable is the surface's responsibility.** *Test: if a surface recomputes availability instead of calling the capability, that is the smell — it should ask, not re-derive.*

## V5 — The registry is a declaration, at the Schema's altitude · settled (2026-07-18)

The registry is not a view, a command, or a decoration — and it is not a framework either, for the same reason the Schema is not: it is a **declaration the editor is built from**, not a contribution that runs in it. It is admissible when three things hold — **inert** (no runtime state, no loop), **compiles to standard ProseMirror** (it emits a keymap plugin, plain specs, nothing else), and **inverts no control** (ProseMirror reads it; it never reads or drives ProseMirror). The instant it holds runtime state or subscribes to the editor, it has crossed from declaration into framework. *This amends the venue's triad ("everything is a view, a command, or a decoration; anything else is a framework"), which conflated two altitudes: the triad governs runtime contributions; declarations are a separate category. Carry this to the venue tablet when it is carved.*

## V6 — Collection forks sync from async · settled (2026-07-18)

A verb declares what arguments it needs; a surface collects them. And collection forks, because a ProseMirror command is **synchronous**: a sync surface (a prompt, a keymap) can wrap an arg-verb in a self-prompting command — dispatch-guarded, so the dry run answers applicability without prompting and only a real run collects — while an async surface (the palette's inline field) cannot collect inside a command, and must collect first, then dispatch `run(collected)`. The arg-schema is shared across surfaces; the collection is not.

## V7 — Activity is a readback; domains come from the document's anatomy · settled (2026-07-18)

Availability is universal — every verb answers "can I?" by dry run (V2). Activity is conditional: only a verb that **addresses** a piece of state answers "am I?", and that answer is a **readback** of the state, over a **domain** of values. The document at a selection holds exactly three kinds of local fact — its mark set (membership → boolean), its textblock's **markup**, ProseMirror's own word for type + attrs (identity → one-of-N), and its ancestor path (multiplicity → count) — so the document-side domains enumerate completely, from the anatomy, not from us. Openness enters only at the two by-charter extension points: attrs, and plugin state (the other readback source; open-ended because plugins are). A verb that creates (insert) or moves along history (undo) addresses nothing and is honestly mute — "action" is not a fourth shape but the absence of one. *Two axes, never flattened: source (document | plugin state) × domain — the first is closed, the second is what a surface renders. Provenance: the plugin-state source, admitted by charter, was exercised 2026-07-19 by the highlight specimen — its verb reads a match count from the plugin's own state, and the toolbar lights on it without knowing the source.*

## V8 — Consumers project the registry · settled (2026-07-18)

The registry's consumers are not only surfaces. Every consumer projects the one list into its **native representation**: a human surface turns domains into furniture — boolean → toggle, one-of-N → dropdown or radio row, count → badge — which makes a toolbar literally *a form bound to the selection*; a machine consumer turns domains into signatures — a test, a macro, an agent's tool manifest. Surfaces are the human subclass of consumers; the plugin cares about neither, which is V4 said from the far side. *Homecoming: VS Code's command registry — commands declared once, keybindings and palette derived, extensions invoking programmatically — is this shape at scale. Provenance: proven by the strip-test (remove all surfaces from the model's account; the first two thirds never mentioned them) and by the venue's zeroth rig, a headless console consumer.*

## V9 — An enumerable domain is declared once and expanded by projection · pinned (2026-07-18)

Block type is not seven verbs; it is **one verb over the domain of textblock markups**, whose per-member forms — buttons, chords, palette items — are produced by a projection (`expand`) that curries the verb across its domain, deriving each form's boolean readback from the verb's single member-valued one. Exclusivity needs no declaration: a node has exactly one markup. *Pinned, the build as its test: if the expansion cannot pass through `toKeymap`/`toolbarSpecs` unchanged, that friction is the verdict and block types fall back to N declared verbs. First run (2026-07-18): passed — both projections consumed the forms unchanged; `expand` is ~20 lines. Held pinned, not settled, until a second consumer (the palette) also eats the forms without apology.*

## V10 — The composition law · settled (2026-07-19)

A plugin declares verbs by **exporting plain data**; **composing them is the host's single act**; the package is needed only to *project*, never to *declare*. The entry is a structural contract — like NodeSpec, which no one imports a class to write — so a foreign plugin (spreads, fragmentview) pays zero dependency to speak. Composition (`composeVerbs`) is the only place normalization happens and the place a **duplicate id is refused at build time**, the same law the keymap projection applies to chords: refusal is a luxury of host-scale composition — one point sees every claim — and VS Code's unrefusable extension keybindings are the standing evidence of what it costs to lack it. Three corollaries ride along: **extra properties are preserved, never refused** (the NodeSpec allowance; prosemirror-tables' `tableRole` is the precedent); **host sovereignty is free** — entries are data, so re-keying, stripping, or overriding is a `map` before composing, not an API; and **a set guards its nouns** — a verb set returns only entries whose node and mark types exist in the schema it was given, so composing a plugin's verbs into a host whose schema lacks its nouns yields nothing rather than entries that crash. *Homecoming: VS Code's contribution points — extensions declare commands and keybindings as manifest data, the host composes, the id is the joint between declaration and implementation.*

## V11 — The keyboard is a stack of courts · settled (2026-07-19)

The keyboard the registry governs is the **named keys only** — the typing stream never enters a keymap; ProseMirror's input machinery owns it. Named keys carry two kinds of binding: a **chord** summons one verb (the key is one summoner among several); a **policy** is one key carrying an ordered chain resolved by position (Enter). The base keymap is not a floor — beneath every keymap sits only the browser's unreliable contenteditable, which baseKeymap exists to pave over — so it is an **imported policy layer, same species as ours**, seated openly as the last court. The law forks by layer: **refusal within a layer, ordering across layers** — cross-layer shadowing is the mechanism (list Enter over base Enter), so what the stack owes is not refusal but **sight**: `describeKey`, which answers for any key who claims it, in what order, and, given a state, who would take it now; and the **audit**, its sweep — every key with more than one claimant, reported for the host's eye, refusing nothing. A plugin's keys arrive the same two ways its verbs do: chords on its entries, policies as exported named bindings — and only the host seats the layers. *Homecomings: Emacs keymap precedence with `describe-key`; VS Code's Troubleshoot Keybindings. Limit stated honestly: describe sees layers and claims, never inside an imported `chainCommands`.*

## V12 — Plugins ship verbs; hosts ship chrome · settled (2026-07-19)

A plugin's public face is: its **nouns** (schema specs), its **verbs** (entries), its **policies** (named key bindings), and its **triad contributions** — the document-anchored presentation it has always legitimately owned: node views, decorations, pointer handlers on document content. What a plugin never ships is **chrome** — toolbars, palettes, dialogs, panels, anything that floats outside the document and summons doings from a distance — because everything chrome needs from it is already in the declarations. The host builds chrome once, for all plugins at the same time, by consuming the registry. The sharpening that earned the stone: "UI" flattened two categories — the line is *document-anchored* (plugin's, the triad's territory) vs *document-external* (host's). And the ecosystem this implies is not mandatory by construction: the contract is structural data, so a plugin that declares verbs has coupled to a shape, not a package. *Homecoming: the Language Server Protocol — servers declare capabilities and commands and render nothing; editors own every surface; the contract between them is data; the ecosystem that grew on it is lean and disciplined. Provenance: proven 2026-07-19 by the highlight specimen (real state, real decorations, zero chrome, zero imports from the registry) driven by venue chrome that doesn't know it exists — with both collection joints exercised the same day. Hostile cases run before carving: cell-selection overlays, column-resize grips, pagination rendering, find-and-replace — all decompose along the line.*

## Vocabulary rulings (2026-07-18)

Adopted, having survived the three-paragraph compression test: **domain** (a slot's value space), **readback** (reading its current value; the verb's optional `read`), and **markup** — not coined but adopted from ProseMirror itself (`hasMarkup`). Dissolved, needing no names: *family* (an enumerable domain) and *shape* (a kind of domain). Rejected: *slot* as a carved term (collides with shadow-DOM vocabulary in the very components that consume this registry) — plain prose says "the state a verb addresses". Left in the drawer: the grammar pair (*transitive*, *conjugation*), available if teaching starves without them.

Dissolved (2026-07-19): **active** — the boolean readback wearing its own name. A toggle reads its domain like every other verb; the contract's one readback field is `read`, and a surface lighting on truthiness is that surface's native rendering, not the registry's vocabulary. Adopted the same day: **chord** vs **policy** (the keyboard stone's two binding kinds) and **focus scope** (the irreducible remainder of availability — see open questions).

## The surfaces ruling (2026-07-18)

The plugin stays lean: `src/verbs/` holds the registry and its pure projections — exactly the contents of the future package. The web components and every other consumer are **venue furniture**, in `src/surfaces/`, and stay behind at extraction. This closes the where-do-the-components-go question; the import direction (surfaces read verbs, never the reverse) is the boundary made mechanical.

## Open questions

- **Collection** · half-built — the sync half exists (2026-07-19): `collectingCommand` wraps an arg-verb dispatch-guarded, exactly as V6 prescribed — the dry run never collects, only a real run asks — and the venue's `window.prompt` chrome proved the seam (link's Mod-k and 🔗 both collect). Prefill-from-readback is built the same day: link's readback is the href you stand in, and the collector offers it back, ready to edit — domains as shared vocabulary between value-back and value-forward, demonstrated. Still open: the async half (a surface that collects first, then dispatches — the palette's field), and the `args[].type` vocabulary, which belongs to whoever collects and firms up as collectors do.
- **The default member** · open — one-of-N surfaces raise it: is "paragraph as the domain's zero" a structural fact or a convenience? It decides whether re-pressing the current member may toggle back to a default. Until decided, one-of-N furniture is honest radio: lit when current, no-op when pressed again.
- **Focus scope** · open — the one availability guard no dry run can answer: *which surface holds the keyboard*. Editor state doesn't know whether the editor, the palette, or nothing has focus — VS Code's `when` clauses exist largely because its commands can't be dry-run, and our dry-run stone dissolves every use of them *except this one*. It also owns the outside country: a window-level summon chord (the palette's Mod-k) lives beyond the editor's keymaps entirely. The same question as the unified surface's focus handoff, seen from the keyboard's side.
- **The unified surface** · open — the intended surface is one hovering element that is a toolbar on a selection and morphs into a Raycast-grade command palette when summoned, all on ProseMirror commands. The confident description exists; the hard part is the focus handoff (the toolbar never takes focus; the palette must) — the focus-scope question above, seen from the surface's side. Deferred.
- **The top layer** · open — `popover` and the top layer are the more platform-native way to float the surface, unverified against the never-take-focus discipline.
- **Extraction** · closed (2026-07-19) — done: this repo. The trigger was the healthy one — real consumers pulling (prosemirror-spreads, the pagination plugin), not ripeness declared from inside. Fresh history by ruling; TypeScript, minimal toolchain chosen on merit (tsc + vitest, no bundler); the tablet traveled with the package. pm-testing-venue remains the proving ground, hosting this as its specimen through a `file:` dependency, its surfaces staying behind as furniture per the surfaces ruling. npm publication is a separate decision, deliberately untaken.
