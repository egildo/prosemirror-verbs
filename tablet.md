# The Tablet — prosemirror-verbs

The founding principles of prosemirror-verbs. When code and a principle disagree, one of them is wrong and the disagreement is a finding, never routed around.

Every claim carries a mark: **settled** (decided, build on it), **pinned** (held, with a falsifiable test attached), or **open** (undecided, with its reason stated). Confident prose never closes an open question.

prosemirror-verbs began inside pm-testing-venue and inherits that venue's law. Where a ruling here amends one of the venue's stones, it says so; the venue's own tablet is parked, so those amendments are recorded to be carried up when it is carved.

Since 2026-10-19 the register itself lives in **verbr**, the library this package was generalised into, and prosemirror-verbs is its ProseMirror profile (V16). The stones keep their history. Where verbr changed a name or a mechanism, the stone carries a dated amendment rather than a silent rewrite.

## V1 — The verb-Schema · settled

ProseMirror registers the document's **nouns** — nodes and marks — in its `Schema`, declaratively, each with a spec. It leaves the **verbs** — commands — as bare functions, with no registry. This is that missing register: verbs, and how they are summoned, declared once as data. ProseMirror ships a noun-registry and no verb-registry; every serious editor rebuilds the missing layer, so the asymmetry is real and the name says the whole thing.

## V2 — Availability is a dry run · settled

A `Command` is `(state, dispatch?, view?) => boolean`, and it decides applicability before `dispatch` is consulted — so calling it without a dispatch is a free, side-effect-free question: "would this apply right now?". Availability needs no separate declaration; it falls out of the command. But *availability* and *activity* are two different questions: `toggleMark(strong)(state)` is true whether or not the mark is on, so the dry run says *enabled*, never *on*. Activity — is the mark lit — is a property of the selection and the document, carried by the verb's own readback, `read`. *(Amended 2026-07-19: the field here was originally `active`; the one-readback ruling dissolved it into `read` — see Vocabulary rulings.)*

## V3 — Verbs are declared or derived · settled (amended 2026-07-29)

A verb enters the registry two ways. **Declared:** hand-written entries, the way `prosemirror-schema-basic` ships a starter set. **Derived:** computed from the schema (`markVerbs`, `insertVerbs`), availability answered by ProseMirror's own `insertPoint` — the noun-equivalent of the command dry run. The verb-Schema does not merely sit beside the noun-Schema; it reads it and generates verbs from its content expressions. *Provenance: derivation was proven on the insert list, 2026-07-18 — availability is position-aware, and a node's required attributes become an arg-verb's arg-schema. Marks joined 2026-07-29: `markVerbs` derives one capability per mark, an attr-carrying mark (a link's href) becoming an arg-verb whose readback is the value you stand in; `basicVerbs` is now that derivation dressed in the conventional taste, so a schema carrying an underline gets the same readback and the same gate as the four anyone thought about.*

**Two clauses on derivation, added 2026-07-29 · pinned**, with the round's own evidence rather than argument:

- **Derivation's reach is the readback's reach.** A derived verb must *address* something, and a selection can only name what V7 already enumerated — the mark set, the textblock's markup, the ancestor path. So an attribute on a node a selection names is derivable, and an attribute reached through a plugin's own resolver is not, whatever the schema says. Worked case: prosemirror-spreads' `table:abbr` (attr on a selectable header) would derive; `table:column-width` (attr on a `table_col` found through a grid map) never could. The boundary is drawn by a standing stone, not invented for the occasion.
- **The schema declares what is grammatically legal, never what is legitimately user-creatable** — so the plugin that owns a noun must be able to say so, through an `authoring` hint on the NodeSpec: `sealed` (everything reachable only through me is mine) and `insert` (false, or the command to use instead of `createAndFill`). This is a **capability fact, not taste** — no second editor could reasonably disagree that a table cell is not a top-level insert — which is the mirror of V12's test: taste went to the host because a host can disagree; this stays with the plugin because no host can. It rides on the spec under the allowance `tableRole` and `spreadsRole` already use.

*Amended 2026-10-19: an attr-carrying mark derives a **set**, not a toggle. Its command was `toggleMark(type, attrs)`, and a toggle cannot say *change the address*: with the cursor in a link it took the link off whatever you typed next, and over a selected link it removed it — while the field above showed the very address you meant to replace. Now the command acts on what the readback shows: values given are written onto the selection, or onto the whole mark the cursor stands in; no value takes the mark away. So the argument is optional at the door, because its absence means something — no address is no link. Verified in the venue: editing the link field rewrites the address, emptying it removes the link.*

*Why it isn't cosmetic, recorded because it was nearly filed as tidiness: with spreads installed the venue's register carried ten derived table verbs, and `insert:table_cell` genuinely fired — one click left a two-column table with a three-cell row, past every structural command spreads wrote and past its enforcement. Verified live before the fix, 2026-07-29, then undone. Pinned rather than settled: one plugin's schema, hours old. The falsifiable attachment is `test/derive.test.ts`, which asserts the closure names `caption/cell/row` and not `text`, `paragraph` or the container itself. What would move it: a real schema that needs an interior type derived anyway — then `sealed` is too coarse a brush and the per-spec override (designed, declined 2026-07-29) comes back.*

## V4 — The API grants capabilities; a surface holds responsibilities · settled (2026-07-18)

The verb-Schema **grants capabilities** — pure, single-sourced computation of what is *possible* and *available*: the command dry run, insertability via `insertPoint`, derivations like `insertVerbs`. A **surface holds responsibility** — *curation* (which of the possible to show), presentation, interaction — consuming those capabilities plus its own conf. Logic is shared and single-sourced, so two surfaces can never disagree about what is possible; judgment and presentation are per-surface. This dissolves the possible-vs-desirable tension rather than answering it: **possible is the API's capability, desirable is the surface's responsibility.** *Test: if a surface recomputes availability instead of calling the capability, that is the smell — it should ask, not re-derive.*

## V5 — The registry is a declaration, at the Schema's altitude · settled (2026-07-18)

The registry is not a view, a command, or a decoration — and it is not a framework either, for the same reason the Schema is not: it is a **declaration the editor is built from**, not a contribution that runs in it. It is admissible when three things hold — **inert** (no runtime state, no loop), **compiles to standard ProseMirror** (it emits a keymap plugin, plain specs, nothing else), and **inverts no control** (ProseMirror reads it; it never reads or drives ProseMirror). The instant it holds runtime state or subscribes to the editor, it has crossed from declaration into framework. *This amends the venue's triad ("everything is a view, a command, or a decoration; anything else is a framework"), which conflated two altitudes: the triad governs runtime contributions; declarations are a separate category. Carry this to the venue tablet when it is carved.*

## V6 — Collection forks sync from async · settled (2026-07-18)

A verb declares what arguments it needs; a surface collects them. And collection forks, because a ProseMirror command is **synchronous**: a sync surface (a prompt, a keymap) can wrap an arg-verb in a self-prompting command — dispatch-guarded, so the dry run answers applicability without prompting and only a real run collects — while an async surface (the palette's inline field) cannot collect inside a command, and must collect first, then dispatch `run(collected)`. The arg-schema is shared across surfaces; the collection is not.

*Amended 2026-10-19: the fork stands, and both halves now end at one door. The sync wrap is `commandFor(register, id, { args, collect })` — verbr's `invoke` shaped as a Command — whose dry run never collects and whose real run asks only when an arg-verb arrives without args. The async half is the surface's field, which commits by running the id with args through the same door. `collectingCommand` and the spec's `write` are gone; what they did is one function now, so a field cannot accept what a chord would refuse.*

## V7 — Activity is a readback; domains come from the document's anatomy · settled (2026-07-18)

Availability is universal — every verb answers "can I?" by dry run (V2). Activity is conditional: only a verb that **addresses** a piece of state answers "am I?", and that answer is a **readback** of the state, over a **domain** of values. The document at a selection holds exactly three kinds of local fact — its mark set (membership → boolean), its textblock's **markup**, ProseMirror's own word for type + attrs (identity → one-of-N), and its ancestor path (multiplicity → count) — so the document-side domains enumerate completely, from the anatomy, not from us. Openness enters only at the two by-charter extension points: attrs, and plugin state (the other readback source; open-ended because plugins are). A verb that creates (insert) or moves along history (undo) addresses nothing and is honestly mute — "action" is not a fourth shape but the absence of one. *Two axes, never flattened: source (document | plugin state) × domain — the first is closed, the second is what a surface renders. Provenance: the plugin-state source, admitted by charter, was exercised 2026-07-19 by the highlight specimen — its verb reads a match count from the plugin's own state, and the toolbar lights on it without knowing the source.*

## V8 — Consumers project the registry · settled (2026-07-18)

The registry's consumers are not only surfaces. Every consumer projects the one list into its **native representation**: a human surface turns domains into furniture — boolean → toggle, one-of-N → dropdown or radio row, count → badge — which makes a toolbar literally *a form bound to the selection*; a machine consumer turns domains into signatures — a test, a macro, an agent's tool manifest. Surfaces are the human subclass of consumers; the plugin cares about neither, which is V4 said from the far side. *Homecoming: VS Code's command registry — commands declared once, keybindings and palette derived, extensions invoking programmatically — is this shape at scale. Provenance: proven by the strip-test (remove all surfaces from the model's account; the first two thirds never mentioned them) and by the venue's zeroth rig, a headless console consumer. Second provenance (2026-07-27), and the stone's own sentence landing literally: `controlSpecs` projects each entry into the control its declaration already implies — no args → a button, one arg with a domain → a select, one arg without a domain but with a value readback → a **field**. (Those three names became four kinds and a separate drawing in V15; the projection is the same act.) Nothing was declared for it; the fork was always in the data, and `toolbarSpecs` had simply been collapsing every readback to `!!read(state)` because a strip of buttons can only light. Two projections now stand side by side over one registry, and the toolbar is a form bound to the selection in the plain sense of the word — the venue shows a link's href and a cell's formula as editable fields, in the bar.*

*Amended 2026-10-19: the projection is verbr's `project`, and what it yields is **plain JSON** — `enabled`, `pressed` and `value` read from the state, no function anywhere. A surface re-projects when the state changes and runs by id. The machine consumer this stone named is real there too: `verbr/tools` turns the same projection into an agent's tool manifest.*

## V9 — An enumerable domain is declared once and expanded by projection · pinned (2026-07-18)

Block type is not seven verbs; it is **one verb over the domain of textblock markups**, whose per-member forms — buttons, chords, palette items — are produced by a projection (`expand`) that curries the verb across its domain, deriving each form's boolean readback from the verb's single member-valued one. Exclusivity needs no declaration: a node has exactly one markup. *Pinned, the build as its test: if the expansion cannot pass through `toKeymap`/`toolbarSpecs` unchanged, that friction is the verdict and block types fall back to N declared verbs. First run (2026-07-18): passed — both projections consumed the forms unchanged; `expand` is ~20 lines. Held pinned, not settled, until a second consumer (the palette) also eats the forms without apology.*

*Amended 2026-10-19: `expand` now gives each form its own command's dry run as availability, which is sharper than the base's gate — the base may run here while this member may not. The forms pass through verbr's `compose`, `project` and the keyboard unchanged, and the palette has eaten them since 2026-08-03. Whether that settles the stone is its author's call.*

## V10 — The composition law · settled (2026-07-19)

A plugin declares verbs by **exporting plain data**; **composing them is the host's single act**; the package is needed only to *project*, never to *declare*. The entry is a structural contract — like NodeSpec, which no one imports a class to write — so a foreign plugin (spreads, fragmentview) pays zero dependency to speak. Composition (`composeVerbs`) is the only place normalization happens and the place a **duplicate id is refused at build time**, the same law the keymap projection applies to chords: refusal is a luxury of host-scale composition — one point sees every claim — and VS Code's unrefusable extension keybindings are the standing evidence of what it costs to lack it. Three corollaries ride along: **extra properties are preserved, never refused** (the NodeSpec allowance; prosemirror-tables' `tableRole` is the precedent); **host sovereignty is free** — entries are data, so re-keying, stripping, or overriding is a `map` before composing, not an API; and **a set guards its nouns** — a verb set returns only entries whose node and mark types exist in the schema it was given, so composing a plugin's verbs into a host whose schema lacks its nouns yields nothing rather than entries that crash. *Homecoming: VS Code's contribution points — extensions declare commands and keybindings as manifest data, the host composes, the id is the joint between declaration and implementation.*

*Amended 2026-10-19: the law holds and its single act moved. Composing is verbr's `compose(sets, vocabulary)`, which refuses a duplicate id at build exactly as `composeVerbs` did. Normalization left composition: `fromCommands` turns a plugin's command-shaped entries into verbs before composing — a bare command's dry run becoming its `enabled` — and the host calls it, so the plugin still pays nothing. The contract a plugin writes did not change: `{ id, command, read?, enabled?, args? }`, plain data.*

## V11 — The keyboard is a stack of courts · settled (2026-07-19)

The keyboard the registry governs is the **named keys only** — the typing stream never enters a keymap; ProseMirror's input machinery owns it. Named keys carry two kinds of binding: a **chord** summons one verb (the key is one summoner among several); a **policy** is one key carrying an ordered chain resolved by position (Enter). The base keymap is not a floor — beneath every keymap sits only the browser's unreliable contenteditable, which baseKeymap exists to pave over — so it is an **imported policy layer, same species as ours**, seated openly as the last court. The law forks by layer: **refusal within a layer, ordering across layers** — cross-layer shadowing is the mechanism (list Enter over base Enter), so what the stack owes is not refusal but **sight**: `describeKey`, which answers for any key who claims it, in what order, and, given a state, who would take it now; and the **audit**, its sweep — every key with more than one claimant, reported for the host's eye, refusing nothing. A plugin's keys arrive the same two ways its verbs do: chords on its entries, policies as exported named bindings — and only the host seats the layers. *Homecomings: Emacs keymap precedence with `describe-key`; VS Code's Troubleshoot Keybindings. Limit stated honestly: describe sees layers and claims, never inside an imported `chainCommands`.*

*Amended 2026-10-19: the verb layer reads its chords from the taste (`keys`), not from the entry, so a host rebinds a chord the way it renames a verb. Each chord runs through `commandFor`, the one door.*

## V12 — Plugins ship capabilities; hosts ship verbs and chrome · settled (2026-07-19; amended 2026-07-29)

A plugin's public face is: its **nouns** (schema specs), its **capabilities** (what it can do and what it can tell you: id, command, readback, gate, arg-schema), its **policies** (named key bindings), and its **triad contributions** — the document-anchored presentation it has always legitimately owned: node views, decorations, pointer handlers on document content. What a plugin never ships is **chrome** — toolbars, palettes, dialogs, panels, anything that floats outside the document and summons doings from a distance — because everything chrome needs from it is already in the declarations. The host builds chrome once, for all plugins at the same time, by consuming the registry. The sharpening that earned the stone: "UI" flattened two categories — the line is *document-anchored* (plugin's, the triad's territory) vs *document-external* (host's). And the ecosystem this implies is not mandatory by construction: the contract is structural data, so a plugin that declares capabilities has coupled to a shape, not a package. *Homecoming: the Language Server Protocol — servers declare capabilities and commands and render nothing; editors own every surface; the contract between them is data; the ecosystem that grew on it is lean and disciplined. Provenance: proven 2026-07-19 by the highlight specimen (real state, real decorations, zero chrome, zero imports from the registry) driven by venue chrome that doesn't know it exists — with both collection joints exercised the same day. Hostile cases run before carving: cell-selection overlays, column-resize grips, pagination rendering, find-and-replace — all decompose along the line.*

*Amended 2026-07-29 (Egildo's ruling, 2026-07-28: "split the entry — capability stays, taste moves"). The original stone drew the line at chrome and stopped one step short: an entry still carried a **name**, a **glyph**, a **chord** and a **category**, which are not chrome but are not the plugin's either. They are how a particular editor, for a particular audience, in a particular language, chooses to present a doing — and a plugin knowing them is the same category error as a plugin owning a toolbar, arriving one layer lower down. So the entry splits. What only the plugin can know stays with it: that a formula lives on a `td` and not a `th`, that this command dry-runs false outside a cell, that this argument is a number. What only the host can know moves to the host: what to call it, which glyph it wears, which chord answers to it, which section it sits in — and the mechanism is V13. The rule that tells them apart, and the one to apply to any new field: **could a second editor reasonably disagree?** If yes, it is taste. Provenance: prosemirror-spreads shed its taste the day this was carved — eighteen capabilities carrying nothing but id, command, readback, gate and args, dressed entirely from the venue's own file. What the shed cost, stated honestly, is that a bare install comes up spelled by an id-humanizer; the answer is the suggested-taste export in V13, which is an offer the host seats, not cargo riding on the verb.*

## V13 — Taste is a cascade of layers · pinned (2026-07-29)

If taste is the host's (V12), the host needs somewhere to put it, and the answer is not a second declaration but a **cascade**: an ordered stack of layers over the composed register, each a `{ name, match?, attrs }` bag, later winning per key. Composition and attribution are the host's **two acts** and they stay two, because they answer different questions — *what can this editor do* and *what shall we call it, where does it go, what does it answer to* — which is why a venue writes them as two files.

Four clauses:

- **A layer sees the register as resolved so far**, not as declared. That is what makes these layers rather than a pile of independent patches: a later layer can match on what an earlier one derived (*everything unbounded goes on the docked bar*), so judgements compose instead of being restated per verb.
- **Capability keys are closed to layers.** A layer that reaches for `id`, `command`, `read`, `enabled` or `args` is refused at build time — the same posture composition takes to a duplicate id, and for the same reason: taste may rename a verb, never redefine what it does.
- **What a stack owes is sight, not refusal** — V11's law, pointed at attributes instead of keys. `describe(id)` answers, for any verb, which layer claimed which attribute and who won; `audit()` sweeps every contested pair. The first time a control turns up somewhere you didn't put it, that is the instrument you will want.
- **The bag is open**, under the allowance the entry contract already carries. A surface may contribute a layer whose vocabulary this package never learns — `room`, `manner`, `priority`, `unavailable` — and the projections carry it through untouched to the element that acts on it.

Two things keep install-and-go true under the split. The **naming default is itself a layer**, seated first, deriving a label from the id (`table:add-row-after` → "Add row after") — a default in the cascade, visible in `describe`, overridable by anything, rather than a fallback buried in code. And a plugin may ship **suggested taste as a separate export**: inert data keyed by id, which the host seats in one line or ignores entirely. That is not a back door for the taste V12 just evicted, and the difference is exactly what the doctrine cares about — it must be seated to have any effect, it loses to every host layer above it, and `describe` names it as the claimant, so the provenance of every glyph on screen is answerable.

*Pinned, with its test. The venue's stack is five layers and does real work: `room` derived from the declaration's own shape (no args ⇒ a glyph; a domain or a number ⇒ bounded; a lone text argument ⇒ **unbounded**), `manner` matched off `room` (unbounded lifts onto a docked value bar, because a formula or a caption cannot fit beside a caret), curation by `manner: 'none'` said as data rather than as `.filter()` calls, and hiding what dry-runs unavailable. It collapsed twenty-one controls into eleven on one row and deleted two spec arrays, four filters and a plugin that swapped them on selection. Falsifiable two ways: if a second real host cannot express its judgements without matching id-by-id, the layers are decoration and a plain per-id override table is the honest shape; and if hiding-not-dimming turns out to be wrong for hands, the derivation above loses its best evidence. One venue, days old — held, not settled. A finding already banked on the way: hiding made every loose `enabled` gate visible at once, because a control that vanishes where it shouldn't is louder than one that greys.*

*Amended 2026-10-19 — **the cascade is verbr's `applyTaste`, and taste became data.** A layer no longer holds a function: `match` became `where`, attribute equality over the declaration's shape (`id` exact or `prefix*`, `kind`, `argType`) and over what earlier claims resolved; and a value that must be computed names a function the host holds (`{ derive: 'room' }`), refused at build when the host holds none. Taste arrives as **documents** stacked root-first — a plugin's suggested taste is simply a document's `verbs` — and within one document the per-verb entries come before its layers, which is why the venue now writes its readings (room, placement, the value bar) as a document of their own. The naming default, the closed capability keys and `describe`/`audit` stand, joined by `orphans`: taste that reached no verb. One word left the open bag: `unavailable` is a capability in verbr (the *why not* a verb names), so hiding what cannot run became the surface's own setting, which it always was.*

*The falsifiable clause got its test. Three venue pages now express every judgement as data, with two named derivations (room, the icon translation) and no predicate anywhere. Id-by-id matching did appear — the structured page seats its exceptions per id — but beside family globs, not instead of them.*

## V14 — The register has structure: facts derived, opinions attributed · pinned (2026-07-29)

ProseMirror's `Schema` does not merely *list* nodes — it declares **how they relate**, through content expressions and groups, and that nesting is half of what makes it a schema rather than a dictionary. This register listed verbs and declared no relations at all, so **V1's analogy ran at half strength from the day it was written**. Worse, the relations that did exist were thrown away: `table:row-region:head` states two levels of nesting out loud in its id and nobody parsed it; `expand` held the base→form edge in its hand as it minted the children and dropped it; `controlSpecs` destroyed grouping into `{separator: true}` markers before any consumer could see it.

The repair needs no fourth idea, which is the strongest evidence it is the right one. Relations sort three ways, along lines already carved:

- **Facts are derived, never declared.** Conjugation is not an opinion — `expand` curried one verb over its domain and minted the ids itself — so the edge is recovered by pure computation (`relations`), and there is no field to be wrong. Alternation is *implied* by conjugation and is a query, never a second stored edge; the second copy is always the one that goes stale.
- **Opinions are attributed.** Which section a verb sits in is taste — one editor groups by document object, another by task — so it stays an attribute in the cascade (V13), where a host can disagree and `describe` will say who won. Nesting is a `/` in that same string.
- **Sections are the projection's parameter, which it has always taken.** A list of ids becomes a list of `{ id, label?, icon?, as?, parent? }`. Hence the seat rule: **taste about a verb lives in the cascade; taste about a section lives in the section list** — two seats, two questions, neither restating the other.

The refusals matter as much as the shape, and each has a reason rather than a preference. **No `parent` field on entries** — derivable, and a field can lie where a derivation cannot; the honest cost is that the edge rides the id convention, so a host re-keying entries loses it, which is accepted because *losing an edge is degraded and asserting a false one is wrong*. **No multi-parent** — a verb has one seat or a strip cannot draw it; findability under several headings is what `keywords` has been declared for since day one and never served. **No group registry** with its own compose-and-refuse machinery: it is a list a projection eats. **No `when`-style conditions on sections** — a section is present iff something in it dry-runs available, which is `#trimSeparators` generalised from a divider to a whole group. **No ordering fields**: VS Code needs `"navigation@1"` because contributions arrive from manifests it cannot order; one host writing one array does not, which is V10's refusal luxury in a third place.

*Pinned, with its attachments. `controlSpecs` is now a flatten over `controlTree` and its output was proved **byte-for-byte identical** across the refactor before anything else was believed — the strip is one layout among several rather than the projection's only answer. `controlTree` carries the `audit()` that `relations` deliberately lacks (audit exists where claims compete; derived facts don't), and it reports a real condition nothing could see before: a host drawing a domain verb **and** its own conjugated forms — two equally valid renderings of one declaration, with nobody having chosen. The venue avoids exactly that by hand in its curation layer. What would move this stone: a second real layout needing a relation that neither derived-conjugation nor attributed-containment can express — then the three-way sort is too coarse. Observed and deliberately **not** modelled: pairing (add-before/add-after, split/join, undo/redo) — real, symmetric, and used by nothing, so it stays unnamed until a layout asks. Provenance: one venue, hours old. It was proved headless first, through the console rig — the honest way to demonstrate a projection with no element behind it — and rendered the same day (V15): sections draw `inline` or collapse behind one face, and the spreadsheet strip went from thirteen controls to two on the strength of one `as: 'menu'`.*

*Amended 2026-08-03 — **the fourth layout arrives, and the stone's own promise needed one option to keep.** A palette was built on the same tree, the same element and the same section list, and almost nothing was added: sections became headings, and a section the strip collapses became a **page you descend into**.*

*Amended the same day, **and this is the correction worth keeping**: back-navigation was first left to the platform — pages as nested popovers, whose close watcher pops the innermost. Elegant, and wrong, because **nothing owned it**. There was no code and no test; a single `stopPropagation()` added elsewhere in the same session removed *back* and nothing noticed. It could not be checked either — the close watcher is invisible to a headless DOM, and the harness this was built through delivers no keydown events at all — and it could not be layered, since suppressing a close request needs a `preventDefault()` guarantee neither the HTML spec's text nor MDN gives. So the palette became a real element that owns its page stack, and prosemirror-surface split into a base plus two surfaces. The rule this leaves: **a surface that redefines a key must own that key.** Escape means *close* to every user agent and *back* to a palette; no platform can be asked to know the difference, and a capability nobody can test is not a capability. What stays the platform's is everything whose meaning we agree with — the top layer, the backdrop, popover state for the host itself.*

*What was genuinely missing was one word. `controlKind` returned `null` for a verb with no icon — a strip's rule, hard-coded as **the** rule — so `controlTree` could not produce a palette's items at all, while this tablet has said since V8 that an unpromoted verb "stays in the register, reachable by chord and by palette". So the projection now takes `face: 'icon' | 'words'`: which face counts is the **surface's** question, not the projection's, and a palette's face is its label. Curation by omission does not disappear; it moves to where a palette can still express it. Proven the same day: the venue's prose palette draws twenty-nine rows where the strip draws eighteen, and the six that appear only there — headings 4 to 6, the derived inserts — are exactly the ones no strip would ever promote.*

*One curation the palette had to make for itself, and it is the condition `audit()` was built to report: ignoring `manner` brought back **a base drawn beside its own forms** — blocktype next to its eight headings. The answer was already derived rather than declared: `relations` knows which verbs `expand` minted, so the palette drops a base whose forms are in the register and shows the forms. A surface resolving the audit's condition instead of reporting it is the shape this was always going to take.*

*Amended 2026-10-19 — **the sections moved into the taste, and closed.** The section list is a taste document's `sections`, and a verb placed in a section no document declares is **refused at build** — a closed vocabulary where this stone had curation by omission. A starter set's suggested section is therefore a demand on the host: declare it, or move the verb out. Nesting is a section's `parent`; the `/` in the id is only a name now. The attribute is `section`, no longer `group`. A verb with no section is trailed after the sections by verbr; the venue keeps the old rule — no section, no seat — as its own. The `audit()` on the tree went with `controlTree`: the condition it reported is now asked of a projection by whoever draws, with `relations` (the venue's `verbs.miscast()`).*

*And the face option moved with the projection. verbr's `face: 'icon'` first dropped every faceless verb, choices and fields included, where this stone's rule had asked a picture only of a doing. Egildo's ruling, 2026-10-19: **the icon face asks a picture only of an action or a toggle** — a choice wears the member it is on, a value is its field. Carried into verbr the same day, and the venue's workaround deleted.*

## V15 — What it is is deduced; how it is drawn is chosen · pinned (2026-07-29)

The control projection read a declaration's shape and named a **button**, a **field** or a **select** — three words that answer two different questions at once, and a host could disagree with neither. So a toggle was a lit button whether or not you wanted a switch, and a domain verb was a dropdown whether or not you wanted a row of radios.

Two fields, and the split is the same one this tablet keeps making:

- **`kind` is a fact.** `action` (a doing), `toggle` (a doing that is also a state — an action plus a readback, free), `choice` (one argument over a domain), `value` (one argument and a readback). Deduced, closed, never written by a host.
- **`as` is taste.** It defaults from the kind and a cascade layer overrides it, needing no new machinery whatsoever: `passthrough` has always carried any non-capability attribute onto the spec, so `as` reached the surface before anything was built for it. A surface that does not know a word **falls back to the kind's default** — a typo costs a switch, never a control.

The same word one altitude up: a **section** has an `as` too, and `inline` (children as siblings) against `menu` (collapsed behind one face) are two layouts of one tree — which is what V14's tree was for. *Link* is neither kind nor drawing; it is a skin on a button, and CSS gets it.

**Icons are names** (Egildo's ruling, 2026-07-29: *"the light DOM defines how to use them — icon fonts, svg symbol names or whatever"*). `short` is gone. A compact face was a Unicode glyph — `⊕↓`, `⊖│`, `ƒ−` — which is **text pretending to be a picture**: it renders as mojibake wherever the font disagrees, and it leaves an icon-only control with nothing for a screen reader to say. The entry now carries `icon`, a name nothing in this package resolves; whoever draws it decides whether that is an SVG mask, an icon font, or a letter. One vocabulary, no exceptions, and an editor switches from lettering to SVGs by editing a stylesheet rather than a register.

Two consequences worth stating, because both were nearly discovered late. **Curation is unchanged**: the absence of an icon still means no control, exactly where the absence of a compact face used to, so `insert:*` and the headings past H3 stay off a strip for free. And **the accessible name becomes load-bearing**: with no text node there is no name unless one is written, which turns a tooltip into an obligation — a gain, pinned in the surface's tests so it cannot rot.

*Pinned. Provenance: the venue's spreadsheet strip went from thirteen controls to two — `⌖` and one `⊞` holding nine — with no verb removed and nothing declared beyond `as: 'menu'` on one section. Falsifiable: if a real drawing needs the element to know something the four holes cannot carry, the template contract is too narrow and this comes back up. What is deliberately not built: `switch` and `radio`, which change nothing that cannot already be done, and per-control template overrides, which would return the drift that keying by `as` exists to prevent.*

*Amended 2026-07-31, from Egildo's question — "do we have to pre-define what the possibilities are in the verbs plugin?" **No, and we never did.** `as` is an **open vocabulary**: the projection passes any string through and validates nothing, because a closed list of drawings would be this package holding an opinion about appearance, which is the whole thing V15 exists to give away. A surface's own words are its **floor** — what to draw when no template of the host's matched — not a permitted list. Only `kind` is closed, and it must be, because behaviour follows from it.*

*Which turned out to be half true in practice, and the missing half was a real defect: the surface chose a control's **wiring** from the word rather than the kind, so a choice drawn as anything but a `<select>` got select wiring on a button — `<option>`s appended into it, a `change` listener that could never fire, no error anywhere. Fixed there (wiring follows the kind and the element the template handed over), and the same rule then applied one altitude up: **a section is collapsed when it is one, not when it is called one** — with a template, a panel the host wrote `popover` on. A venue can now invent a second kind of section without lying about its name, and the venue's prose page has: `listing`, a real `<ul>` of `<li>` whose two members are the list wraps. **No verb was declared for it** — the classic ordered/unordered dropdown is grouping, which this register has had since V13. What the drawing added was the other case: a `choice` collapsed behind the member its readback answers (`as: 'dropdown'`), which the spreadsheet page's region chooser now is, in place of a `<select>` that could wear neither the venue's font nor its chrome.*

*Amended 2026-10-19: verbr deduces `value` from shape alone — one argument without a domain is a value whether or not it reads back. Its design notes record the choice between the two ancestor rules. The consequence on the prose page: `insert:image` became a field on the docked bar instead of a button that prompts. `kind` stays closed and `as` stays open, in verbr as here.*

## V16 — The register goes home to verbr · settled (2026-10-19)

The register was built three times before it turned out to be one thing: here, in `@sibar/verbs`, and as Nodemirror's action catalogue. **verbr** is their union, generic over any state, and its design notes map every field of this package to its home there. So the generic half left (Egildo's ruling, 2026-10-19, *the clean break*): composition, the cascade, the control projection, sections, the naming default and chord formatting are verbr's `compose`, `applyTaste`, `project`, `NAMING` and the projection's `shortcut`. What stays here is what only ProseMirror can say: **a verb's context is an `EditorState`, what it runs is a `Command`, and a command's dry run is its availability** (V2, unchanged and now the whole reason this package exists); the keyboard as a stack of keymap plugins (V11); the starter sets and derivations that read the noun-Schema (V3, V9); and `relations` (V14).

The door is new and it is verbr's best gift: **every surface runs a verb by id through `invoke`**, which checks availability, applicability and args in one place. `commandFor` is that door shaped as a Command. A chord, a button, a palette row and the console now cannot disagree about what may run, which V4 asked for and only the projection used to honour.

prosemirror-surface moved in step: it eats verbr's projection as plain data and runs everything through a `run(id, args)` it is handed. It still depends on no package; a shape joins them.

*Provenance: the venue's three pages, rebuilt on verbr the same day and checked by hand in the browser — marks, block types, the link field, the row-region dropdown, the formula bar, nested sections, a palette row run through the door. verbr is linked from the local folder (`file:../../verbr`) until it is published; the venue reads verbr's built output, so verbr must be rebuilt after a change. (Later the same day, by Egildo's ruling: not published — installed from its private GitHub repo instead, pinned to a commit by the lockfile and built on install.) spreads-arena was removed the same day.*

## Vocabulary rulings (2026-07-18)

Adopted, having survived the three-paragraph compression test: **domain** (a slot's value space), **readback** (reading its current value; the verb's optional `read`), and **markup** — not coined but adopted from ProseMirror itself (`hasMarkup`). Dissolved, needing no names: *family* (an enumerable domain) and *shape* (a kind of domain). Rejected: *slot* as a carved term (collides with shadow-DOM vocabulary in the very components that consume this registry) — plain prose says "the state a verb addresses". Left in the drawer: the grammar pair (*transitive*, *conjugation*), available if teaching starves without them.

Adopted (2026-10-19, with V16): **section** for what was *group*, verbr's word, and **where** for what was *match* — no longer a predicate but attribute equality, which is the selector language this ruling refused, kept honest by refusing specificity: order is still the only precedence. **Door** for the one place a verb is run.

Adopted (2026-07-29, with V12's amendment): **capability** and **taste** — the entry's two halves, and the pair that finally names what a plugin owes a host. *Verb* keeps its meaning and gains a precise one: a verb is a capability *plus* the taste a host dressed it in, which is why the register a host composes holds verbs and the set a plugin exports holds capabilities. **Layer**, **claim** and **cascade** ride in with V13; *cascade* is borrowed from CSS deliberately, and the loan is honest — ordered sources, later winning per property, with the winner answerable — while `match` is pointedly *not* a selector language (an id, a `prefix*` glob, or a predicate), because the day it needs specificity rules it has stopped being a stack of a host's opinions.

Dissolved (2026-07-19): **active** — the boolean readback wearing its own name. A toggle reads its domain like every other verb; the contract's one readback field is `read`, and a surface lighting on truthiness is that surface's native rendering, not the registry's vocabulary. Adopted the same day: **chord** vs **policy** (the keyboard stone's two binding kinds) and **focus scope** (the irreducible remainder of availability — see open questions).

## The surfaces ruling (2026-07-18)

The plugin stays lean: `src/verbs/` holds the registry and its pure projections — exactly the contents of the future package. The web components and every other consumer are **venue furniture**, in `src/surfaces/`, and stay behind at extraction. This closes the where-do-the-components-go question; the import direction (surfaces read verbs, never the reverse) is the boundary made mechanical. *(Amended 2026-07-19, after both extractions: the ruling's core stands — chrome never enters this package — but "stay behind" evolved: the toolbar surface graduated into its own package, `prosemirror-surface`, per the ecosystem stone's host half. The two packages share no dependency; they join by the spec's structural shape, exactly as plugins join the registry. The console rig and the prompt collector remain venue furniture.)* *(Amended 2026-10-19: the structural shape is now verbr's `Control`, plain data, and the surface holds no verb's function — the spec carries no `command`, and the element calls a door it was handed.)*

## Open questions

- **Collection** · half-built — the sync half exists (2026-07-19): `collectingCommand` wraps an arg-verb dispatch-guarded, exactly as V6 prescribed — the dry run never collects, only a real run asks — and the venue's `window.prompt` chrome proved the seam (link's Mod-k and 🔗 both collect). Prefill-from-readback is built the same day: link's readback is the href you stand in, and the collector offers it back, ready to edit — domains as shared vocabulary between value-back and value-forward, demonstrated. The async half arrived for the single-argument case (2026-07-27): a **field is the collector, inlined** — it shows the readback, you edit it, and it commits through `write(value)`, which is `run({[arg.name]: value})` and needs no `Collector` at all. That closes collect-first-then-dispatch where the argument is one value; the palette's multi-field form is still the open remainder, and `collectingCommand` stays the fallback for what has no control to read — a chord, a palette item, a multi-arg verb (`table:insert`'s rows × cols still prompts). The `args[].type` vocabulary took its first entries the same day, from the collectors that now exist: `text`, `number`, `url` — the field's input type, nothing more claimed. *(2026-10-19: both halves end at verbr's door now — `commandFor` replaces `collectingCommand`, and a field commits by running the id with args. The type vocabulary is verbr's, checked at the door: a link without a scheme is refused.)*
- **The rest of derivation** · open, two of five built (2026-07-29) — marks and repaired inserts stand; three remain, in the order their blockers clear. **Attribute verbs**: an attr with a default, on a node a selection can name, is a verb — `setNodeMarkup` for the command, `node.attrs[name]` for the readback, the field projection already knowing what to do with it. The missing piece is the *domain*: a schema says `{ level: { default: 1 } }` and never says 1–6; `validate` gives a type and nothing more. **Wrap verbs**: blocked on knowledge that isn't in the schema at all — it knows `bullet_list` contains `list_item+`, not that wrapping needs `wrapInList`'s lift-and-join rather than plain `wrapIn`, which lives in prosemirror-schema-list. So wraps are **opt-in** through `authoring.wrap` when they land: derive freely where the schema knows, require a hint where it doesn't. **And one speculation, flagged as speculation because it is the pleasing kind**: `parseDOM` rules enumerate an attribute's value space — someone had to write one rule per legal value, so `heading`'s six `h1`–`h6` entries *are* the blocktype domain we currently hand-list. Cheap to test, untested, and not to be built on until it is.
- **The outward direction** · open, deliberately not taken (2026-07-29) — the round that produced V3's amendment first mapped what VS Code gives an extension that a catalogue doesn't, and found three things this package lacks: **invocation by id** as a public handle (`executeCommand` is that ecosystem's whole interop surface; ours exists only as the venue's hand-rolled console rig), **findability for free** (declare a title, get a palette entry — our `keywords` field has been declared on every entry since day one and serves nothing, because the projection it exists for was never written), and **a standard asker**. The third does not belong here at all: an asker is chrome, so it is prosemirror-surface's, and it is the async-collector question wearing other clothes. Also noted, so the comparison stays honest rather than admiring: we are *ahead* on availability (their `when` clauses exist largely because their commands can't be dry-run) and on placement (their menu contributions are a static manifest; our cascade has sight). Egildo ruled downward over outward, on the grounds that outward is work anyone could do. Standing, with a **palette projection** as its first stone — pure, and the ranking is the part every host would get wrong. *(2026-10-19: verbr answered two of the three without this package building them. **Invocation by id** is `invoke`, and here `commandFor`; **findability** is served — `keywords` ride the projection into the palette's search. And an agent's tool manifest is `verbr/tools`. The standard asker stays the open remainder, and stays chrome.)*
- **The default member** · open — one-of-N surfaces raise it: is "paragraph as the domain's zero" a structural fact or a convenience? It decides whether re-pressing the current member may toggle back to a default. Until decided, one-of-N furniture is honest radio: lit when current, no-op when pressed again.
- **Focus scope** · open — the one availability guard no dry run can answer: *which surface holds the keyboard*. Editor state doesn't know whether the editor, the palette, or nothing has focus — VS Code's `when` clauses exist largely because its commands can't be dry-run, and our dry-run stone dissolves every use of them *except this one*. It also owns the outside country: a window-level summon chord (the palette's Mod-k) lives beyond the editor's keymaps entirely. The same question as the unified surface's focus handoff, seen from the keyboard's side.
- **The unified surface** · open, one joint tested (2026-07-27) — the intended surface is one hovering element that is a toolbar on a selection and morphs into a Raycast-grade command palette when summoned, all on ProseMirror commands. The confident description exists; the hard part is the focus handoff (the toolbar never takes focus; the palette must) — the focus-scope question above, seen from the surface's side. The field forced a first, narrow crossing of exactly that line and it held: a control may take focus where a button may not, because *the editor's selection is state, not focus*, and it survives the blur intact; what the surface owes back is to hand the caret over before running the command (so a node view can reclaim its own seat during the dispatch) and to stay put while engaged (the anchor, reading focus, would otherwise hide the strip the moment you clicked into it). Narrow because a field is not a palette: one control, no keyboard capture, no summon chord. The question stands; the first stone of its floor does not.
- **The top layer** · open — `popover` and the top layer are the more platform-native way to float the surface, unverified against the never-take-focus discipline.
- **Extraction** · closed (2026-07-19) — done: this repo. The trigger was the healthy one — real consumers pulling (prosemirror-spreads, the pagination plugin), not ripeness declared from inside. Fresh history by ruling; TypeScript, minimal toolchain chosen on merit (tsc + vitest, no bundler); the tablet traveled with the package. pm-testing-venue remains the proving ground, hosting this as its specimen through a `file:` dependency, its surfaces staying behind as furniture per the surfaces ruling. npm publication is a separate decision, deliberately untaken. *(2026-10-19: now also verbr's, which this package depends on. Ruled the same day: verbr is not published, and installs from its private GitHub repo.)*
