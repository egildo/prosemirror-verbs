# The Tablet — prosemirror-verbs

The founding principles of prosemirror-verbs. When code and a principle disagree, one of them is wrong and the disagreement is a finding, never routed around.

Every claim carries a mark: **settled** (decided, build on it), **pinned** (held, with a falsifiable test attached), or **open** (undecided, with its reason stated). Confident prose never closes an open question.

prosemirror-verbs began inside pm-testing-venue and inherits that venue's law. Where a ruling here amends one of the venue's stones, it says so; the venue's own tablet is parked, so those amendments are recorded to be carried up when it is carved.

## V1 — The verb-Schema · settled

ProseMirror registers the document's **nouns** — nodes and marks — in its `Schema`, declaratively, each with a spec. It leaves the **verbs** — commands — as bare functions, with no registry. This is that missing register: verbs, and how they are summoned, declared once as data. ProseMirror ships a noun-registry and no verb-registry; every serious editor rebuilds the missing layer, so the asymmetry is real and the name says the whole thing.

## V2 — Availability is a dry run · settled

A `Command` is `(state, dispatch?, view?) => boolean`, and it decides applicability before `dispatch` is consulted — so calling it without a dispatch is a free, side-effect-free question: "would this apply right now?". Availability needs no separate declaration; it falls out of the command. But *availability* and *activity* are two different questions: `toggleMark(strong)(state)` is true whether or not the mark is on, so the dry run says *enabled*, never *on*. Activity — is the mark lit — is a property of the selection and the document, carried by the verb's own readback, `read`. *(Amended 2026-07-19: the field here was originally `active`; the one-readback ruling dissolved it into `read` — see Vocabulary rulings.)*

## V3 — Verbs are declared or derived · settled (amended 2026-07-29)

A verb enters the registry two ways. **Declared:** hand-written entries, the way `prosemirror-schema-basic` ships a starter set. **Derived:** computed from the schema (`markVerbs`, `insertVerbs`), availability answered by ProseMirror's own `insertPoint` — the noun-equivalent of the command dry run. The verb-Schema does not merely sit beside the noun-Schema; it reads it and generates verbs from its content expressions. *Provenance: derivation was proven on the insert list, 2026-07-18 — availability is position-aware, and a node's required attributes become an arg-verb's arg-schema. Marks joined 2026-07-29: `markVerbs` derives one capability per mark, an attr-carrying mark (a link's href) becoming an arg-verb whose readback is the value you stand in; `basicVerbs` is now that derivation dressed in the conventional taste, so a schema carrying an underline gets the same readback and the same gate as the four anyone thought about.*

**Two clauses on derivation, added 2026-07-29 · pinned**, with the round's own evidence rather than argument:

- **Derivation's reach is the readback's reach.** A derived verb must *address* something, and a selection can only name what V7 already enumerated — the mark set, the textblock's markup, the ancestor path. So an attribute on a node a selection names is derivable, and an attribute reached through a plugin's own resolver is not, whatever the schema says. Worked case: prosemirror-spreads' `table:abbr` (attr on a selectable header) would derive; `table:column-width` (attr on a `table_col` found through a grid map) never could. The boundary is drawn by a standing stone, not invented for the occasion.
- **The schema declares what is grammatically legal, never what is legitimately user-creatable** — so the plugin that owns a noun must be able to say so, through an `authoring` hint on the NodeSpec: `sealed` (everything reachable only through me is mine) and `insert` (false, or the command to use instead of `createAndFill`). This is a **capability fact, not taste** — no second editor could reasonably disagree that a table cell is not a top-level insert — which is the mirror of V12's test: taste went to the host because a host can disagree; this stays with the plugin because no host can. It rides on the spec under the allowance `tableRole` and `spreadsRole` already use.

*Why it isn't cosmetic, recorded because it was nearly filed as tidiness: with spreads installed the venue's register carried ten derived table verbs, and `insert:table_cell` genuinely fired — one click left a two-column table with a three-cell row, past every structural command spreads wrote and past its enforcement. Verified live before the fix, 2026-07-29, then undone. Pinned rather than settled: one plugin's schema, hours old. The falsifiable attachment is `test/derive.test.ts`, which asserts the closure names `caption/cell/row` and not `text`, `paragraph` or the container itself. What would move it: a real schema that needs an interior type derived anyway — then `sealed` is too coarse a brush and the per-spec override (designed, declined 2026-07-29) comes back.*

## V4 — The API grants capabilities; a surface holds responsibilities · settled (2026-07-18)

The verb-Schema **grants capabilities** — pure, single-sourced computation of what is *possible* and *available*: the command dry run, insertability via `insertPoint`, derivations like `insertVerbs`. A **surface holds responsibility** — *curation* (which of the possible to show), presentation, interaction — consuming those capabilities plus its own conf. Logic is shared and single-sourced, so two surfaces can never disagree about what is possible; judgment and presentation are per-surface. This dissolves the possible-vs-desirable tension rather than answering it: **possible is the API's capability, desirable is the surface's responsibility.** *Test: if a surface recomputes availability instead of calling the capability, that is the smell — it should ask, not re-derive.*

## V5 — The registry is a declaration, at the Schema's altitude · settled (2026-07-18)

The registry is not a view, a command, or a decoration — and it is not a framework either, for the same reason the Schema is not: it is a **declaration the editor is built from**, not a contribution that runs in it. It is admissible when three things hold — **inert** (no runtime state, no loop), **compiles to standard ProseMirror** (it emits a keymap plugin, plain specs, nothing else), and **inverts no control** (ProseMirror reads it; it never reads or drives ProseMirror). The instant it holds runtime state or subscribes to the editor, it has crossed from declaration into framework. *This amends the venue's triad ("everything is a view, a command, or a decoration; anything else is a framework"), which conflated two altitudes: the triad governs runtime contributions; declarations are a separate category. Carry this to the venue tablet when it is carved.*

## V6 — Collection forks sync from async · settled (2026-07-18)

A verb declares what arguments it needs; a surface collects them. And collection forks, because a ProseMirror command is **synchronous**: a sync surface (a prompt, a keymap) can wrap an arg-verb in a self-prompting command — dispatch-guarded, so the dry run answers applicability without prompting and only a real run collects — while an async surface (the palette's inline field) cannot collect inside a command, and must collect first, then dispatch `run(collected)`. The arg-schema is shared across surfaces; the collection is not.

## V7 — Activity is a readback; domains come from the document's anatomy · settled (2026-07-18)

Availability is universal — every verb answers "can I?" by dry run (V2). Activity is conditional: only a verb that **addresses** a piece of state answers "am I?", and that answer is a **readback** of the state, over a **domain** of values. The document at a selection holds exactly three kinds of local fact — its mark set (membership → boolean), its textblock's **markup**, ProseMirror's own word for type + attrs (identity → one-of-N), and its ancestor path (multiplicity → count) — so the document-side domains enumerate completely, from the anatomy, not from us. Openness enters only at the two by-charter extension points: attrs, and plugin state (the other readback source; open-ended because plugins are). A verb that creates (insert) or moves along history (undo) addresses nothing and is honestly mute — "action" is not a fourth shape but the absence of one. *Two axes, never flattened: source (document | plugin state) × domain — the first is closed, the second is what a surface renders. Provenance: the plugin-state source, admitted by charter, was exercised 2026-07-19 by the highlight specimen — its verb reads a match count from the plugin's own state, and the toolbar lights on it without knowing the source.*

## V8 — Consumers project the registry · settled (2026-07-18)

The registry's consumers are not only surfaces. Every consumer projects the one list into its **native representation**: a human surface turns domains into furniture — boolean → toggle, one-of-N → dropdown or radio row, count → badge — which makes a toolbar literally *a form bound to the selection*; a machine consumer turns domains into signatures — a test, a macro, an agent's tool manifest. Surfaces are the human subclass of consumers; the plugin cares about neither, which is V4 said from the far side. *Homecoming: VS Code's command registry — commands declared once, keybindings and palette derived, extensions invoking programmatically — is this shape at scale. Provenance: proven by the strip-test (remove all surfaces from the model's account; the first two thirds never mentioned them) and by the venue's zeroth rig, a headless console consumer. Second provenance (2026-07-27), and the stone's own sentence landing literally: `controlSpecs` projects each entry into the control its declaration already implies — no args → button, one arg with a domain → select, one arg without a domain but with a value readback → **field**. Nothing was declared for it; the fork was always in the data, and `toolbarSpecs` had simply been collapsing every readback to `!!read(state)` because a strip of buttons can only light. Two projections now stand side by side over one registry, and the toolbar is a form bound to the selection in the plain sense of the word — the venue shows a link's href and a cell's formula as editable fields, in the bar.*

## V9 — An enumerable domain is declared once and expanded by projection · pinned (2026-07-18)

Block type is not seven verbs; it is **one verb over the domain of textblock markups**, whose per-member forms — buttons, chords, palette items — are produced by a projection (`expand`) that curries the verb across its domain, deriving each form's boolean readback from the verb's single member-valued one. Exclusivity needs no declaration: a node has exactly one markup. *Pinned, the build as its test: if the expansion cannot pass through `toKeymap`/`toolbarSpecs` unchanged, that friction is the verdict and block types fall back to N declared verbs. First run (2026-07-18): passed — both projections consumed the forms unchanged; `expand` is ~20 lines. Held pinned, not settled, until a second consumer (the palette) also eats the forms without apology.*

## V10 — The composition law · settled (2026-07-19)

A plugin declares verbs by **exporting plain data**; **composing them is the host's single act**; the package is needed only to *project*, never to *declare*. The entry is a structural contract — like NodeSpec, which no one imports a class to write — so a foreign plugin (spreads, fragmentview) pays zero dependency to speak. Composition (`composeVerbs`) is the only place normalization happens and the place a **duplicate id is refused at build time**, the same law the keymap projection applies to chords: refusal is a luxury of host-scale composition — one point sees every claim — and VS Code's unrefusable extension keybindings are the standing evidence of what it costs to lack it. Three corollaries ride along: **extra properties are preserved, never refused** (the NodeSpec allowance; prosemirror-tables' `tableRole` is the precedent); **host sovereignty is free** — entries are data, so re-keying, stripping, or overriding is a `map` before composing, not an API; and **a set guards its nouns** — a verb set returns only entries whose node and mark types exist in the schema it was given, so composing a plugin's verbs into a host whose schema lacks its nouns yields nothing rather than entries that crash. *Homecoming: VS Code's contribution points — extensions declare commands and keybindings as manifest data, the host composes, the id is the joint between declaration and implementation.*

## V11 — The keyboard is a stack of courts · settled (2026-07-19)

The keyboard the registry governs is the **named keys only** — the typing stream never enters a keymap; ProseMirror's input machinery owns it. Named keys carry two kinds of binding: a **chord** summons one verb (the key is one summoner among several); a **policy** is one key carrying an ordered chain resolved by position (Enter). The base keymap is not a floor — beneath every keymap sits only the browser's unreliable contenteditable, which baseKeymap exists to pave over — so it is an **imported policy layer, same species as ours**, seated openly as the last court. The law forks by layer: **refusal within a layer, ordering across layers** — cross-layer shadowing is the mechanism (list Enter over base Enter), so what the stack owes is not refusal but **sight**: `describeKey`, which answers for any key who claims it, in what order, and, given a state, who would take it now; and the **audit**, its sweep — every key with more than one claimant, reported for the host's eye, refusing nothing. A plugin's keys arrive the same two ways its verbs do: chords on its entries, policies as exported named bindings — and only the host seats the layers. *Homecomings: Emacs keymap precedence with `describe-key`; VS Code's Troubleshoot Keybindings. Limit stated honestly: describe sees layers and claims, never inside an imported `chainCommands`.*

## V12 — Plugins ship capabilities; hosts ship verbs and chrome · settled (2026-07-19; amended 2026-07-29)

A plugin's public face is: its **nouns** (schema specs), its **capabilities** (what it can do and what it can tell you: id, command, readback, gate, arg-schema), its **policies** (named key bindings), and its **triad contributions** — the document-anchored presentation it has always legitimately owned: node views, decorations, pointer handlers on document content. What a plugin never ships is **chrome** — toolbars, palettes, dialogs, panels, anything that floats outside the document and summons doings from a distance — because everything chrome needs from it is already in the declarations. The host builds chrome once, for all plugins at the same time, by consuming the registry. The sharpening that earned the stone: "UI" flattened two categories — the line is *document-anchored* (plugin's, the triad's territory) vs *document-external* (host's). And the ecosystem this implies is not mandatory by construction: the contract is structural data, so a plugin that declares capabilities has coupled to a shape, not a package. *Homecoming: the Language Server Protocol — servers declare capabilities and commands and render nothing; editors own every surface; the contract between them is data; the ecosystem that grew on it is lean and disciplined. Provenance: proven 2026-07-19 by the highlight specimen (real state, real decorations, zero chrome, zero imports from the registry) driven by venue chrome that doesn't know it exists — with both collection joints exercised the same day. Hostile cases run before carving: cell-selection overlays, column-resize grips, pagination rendering, find-and-replace — all decompose along the line.*

*Amended 2026-07-29 (Egildo's ruling, 2026-07-28: "split the entry — capability stays, taste moves"). The original stone drew the line at chrome and stopped one step short: an entry still carried a **name**, a **glyph**, a **chord** and a **category**, which are not chrome but are not the plugin's either. They are how a particular editor, for a particular audience, in a particular language, chooses to present a doing — and a plugin knowing them is the same category error as a plugin owning a toolbar, arriving one layer lower down. So the entry splits. What only the plugin can know stays with it: that a formula lives on a `td` and not a `th`, that this command dry-runs false outside a cell, that this argument is a number. What only the host can know moves to the host: what to call it, which glyph it wears, which chord answers to it, which section it sits in — and the mechanism is V13. The rule that tells them apart, and the one to apply to any new field: **could a second editor reasonably disagree?** If yes, it is taste. Provenance: prosemirror-spreads shed its taste the day this was carved — eighteen capabilities carrying nothing but id, command, readback, gate and args, dressed entirely from the venue's own file. What the shed cost, stated honestly, is that a bare install comes up spelled by an id-humanizer; the answer is the suggested-taste export in V13, which is an offer the host seats, not cargo riding on the verb.*

## V13 — Taste is a cascade of layers · pinned (2026-07-29)

If taste is the host's (V12), the host needs somewhere to put it, and the answer is not a second declaration but a **cascade**: an ordered stack of layers over the composed register, each a `{ name, match?, attrs }` bag, later winning per key. Composition and attribution are the host's **two acts** and they stay two, because they answer different questions — *what can this editor do* and *what shall we call it, where does it go, what does it answer to* — which is why a venue writes them as two files.

Four clauses:

- **A layer sees the register as resolved so far**, not as declared. That is what makes these layers rather than a pile of independent patches: a later layer can match on what an earlier one derived (*everything unbounded goes on the docked bar*), so judgements compose instead of being restated per verb.
- **Capability keys are closed to layers.** A layer that reaches for `id`, `command`, `read`, `enabled` or `args` is refused at build time — the same posture composition takes to a duplicate id, and for the same reason: taste may rename a verb, never redefine what it does.
- **What a stack owes is sight, not refusal** — V11's law, pointed at attributes instead of keys. `describe(id)` answers, for any verb, which layer claimed which attribute and who won; `audit()` sweeps every contested pair. The first time a control turns up somewhere you didn't put it, that is the instrument you will want.
- **The bag is open**, under the allowance the entry contract already carries. A surface may contribute a layer whose vocabulary this package never learns — `room`, `manner`, `priority`, `unavailable` — and the projections carry it through untouched to the element that acts on it.

Two things keep install-and-go true under the split. The **naming default is itself a layer**, seated first, deriving a label from the id (`table:add-row-after` → "Add row after") — a default in the cascade, visible in `describe`, overridable by anything, rather than a fallback buried in code. And a plugin may ship **suggested taste as a separate export**: inert data keyed by id, which the host seats in one line or ignores entirely. That is not a back door for the taste V12 just evicted, and the difference is exactly what the doctrine cares about — it must be seated to have any effect, it loses to every host layer above it, and `describe` names it as the claimant, so the provenance of every glyph on screen is answerable.

*Pinned, with its test. The venue's stack is five layers and does real work: `room` derived from the declaration's own shape (no args ⇒ a glyph; a domain or a number ⇒ bounded; a lone text argument ⇒ **unbounded**), `manner` matched off `room` (unbounded lifts onto a docked value bar, because a formula or a caption cannot fit beside a caret), curation by `manner: 'none'` said as data rather than as `.filter()` calls, and hiding what dry-runs unavailable. It collapsed twenty-one controls into eleven on one row and deleted two spec arrays, four filters and a plugin that swapped them on selection. Falsifiable two ways: if a second real host cannot express its judgements without matching id-by-id, the layers are decoration and a plain per-id override table is the honest shape; and if hiding-not-dimming turns out to be wrong for hands, the derivation above loses its best evidence. One venue, days old — held, not settled. A finding already banked on the way: hiding made every loose `enabled` gate visible at once, because a control that vanishes where it shouldn't is louder than one that greys.*

## Vocabulary rulings (2026-07-18)

Adopted, having survived the three-paragraph compression test: **domain** (a slot's value space), **readback** (reading its current value; the verb's optional `read`), and **markup** — not coined but adopted from ProseMirror itself (`hasMarkup`). Dissolved, needing no names: *family* (an enumerable domain) and *shape* (a kind of domain). Rejected: *slot* as a carved term (collides with shadow-DOM vocabulary in the very components that consume this registry) — plain prose says "the state a verb addresses". Left in the drawer: the grammar pair (*transitive*, *conjugation*), available if teaching starves without them.

Adopted (2026-07-29, with V12's amendment): **capability** and **taste** — the entry's two halves, and the pair that finally names what a plugin owes a host. *Verb* keeps its meaning and gains a precise one: a verb is a capability *plus* the taste a host dressed it in, which is why the register a host composes holds verbs and the set a plugin exports holds capabilities. **Layer**, **claim** and **cascade** ride in with V13; *cascade* is borrowed from CSS deliberately, and the loan is honest — ordered sources, later winning per property, with the winner answerable — while `match` is pointedly *not* a selector language (an id, a `prefix*` glob, or a predicate), because the day it needs specificity rules it has stopped being a stack of a host's opinions.

Dissolved (2026-07-19): **active** — the boolean readback wearing its own name. A toggle reads its domain like every other verb; the contract's one readback field is `read`, and a surface lighting on truthiness is that surface's native rendering, not the registry's vocabulary. Adopted the same day: **chord** vs **policy** (the keyboard stone's two binding kinds) and **focus scope** (the irreducible remainder of availability — see open questions).

## The surfaces ruling (2026-07-18)

The plugin stays lean: `src/verbs/` holds the registry and its pure projections — exactly the contents of the future package. The web components and every other consumer are **venue furniture**, in `src/surfaces/`, and stay behind at extraction. This closes the where-do-the-components-go question; the import direction (surfaces read verbs, never the reverse) is the boundary made mechanical. *(Amended 2026-07-19, after both extractions: the ruling's core stands — chrome never enters this package — but "stay behind" evolved: the toolbar surface graduated into its own package, `prosemirror-surface`, per the ecosystem stone's host half. The two packages share no dependency; they join by the spec's structural shape, exactly as plugins join the registry. The console rig and the prompt collector remain venue furniture.)*

## Open questions

- **Collection** · half-built — the sync half exists (2026-07-19): `collectingCommand` wraps an arg-verb dispatch-guarded, exactly as V6 prescribed — the dry run never collects, only a real run asks — and the venue's `window.prompt` chrome proved the seam (link's Mod-k and 🔗 both collect). Prefill-from-readback is built the same day: link's readback is the href you stand in, and the collector offers it back, ready to edit — domains as shared vocabulary between value-back and value-forward, demonstrated. The async half arrived for the single-argument case (2026-07-27): a **field is the collector, inlined** — it shows the readback, you edit it, and it commits through `write(value)`, which is `run({[arg.name]: value})` and needs no `Collector` at all. That closes collect-first-then-dispatch where the argument is one value; the palette's multi-field form is still the open remainder, and `collectingCommand` stays the fallback for what has no control to read — a chord, a palette item, a multi-arg verb (`table:insert`'s rows × cols still prompts). The `args[].type` vocabulary took its first entries the same day, from the collectors that now exist: `text`, `number`, `url` — the field's input type, nothing more claimed.
- **The rest of derivation** · open, two of five built (2026-07-29) — marks and repaired inserts stand; three remain, in the order their blockers clear. **Attribute verbs**: an attr with a default, on a node a selection can name, is a verb — `setNodeMarkup` for the command, `node.attrs[name]` for the readback, the field projection already knowing what to do with it. The missing piece is the *domain*: a schema says `{ level: { default: 1 } }` and never says 1–6; `validate` gives a type and nothing more. **Wrap verbs**: blocked on knowledge that isn't in the schema at all — it knows `bullet_list` contains `list_item+`, not that wrapping needs `wrapInList`'s lift-and-join rather than plain `wrapIn`, which lives in prosemirror-schema-list. So wraps are **opt-in** through `authoring.wrap` when they land: derive freely where the schema knows, require a hint where it doesn't. **And one speculation, flagged as speculation because it is the pleasing kind**: `parseDOM` rules enumerate an attribute's value space — someone had to write one rule per legal value, so `heading`'s six `h1`–`h6` entries *are* the blocktype domain we currently hand-list. Cheap to test, untested, and not to be built on until it is.
- **The outward direction** · open, deliberately not taken (2026-07-29) — the round that produced V3's amendment first mapped what VS Code gives an extension that a catalogue doesn't, and found three things this package lacks: **invocation by id** as a public handle (`executeCommand` is that ecosystem's whole interop surface; ours exists only as the venue's hand-rolled console rig), **findability for free** (declare a title, get a palette entry — our `keywords` field has been declared on every entry since day one and serves nothing, because the projection it exists for was never written), and **a standard asker**. The third does not belong here at all: an asker is chrome, so it is prosemirror-surface's, and it is the async-collector question wearing other clothes. Also noted, so the comparison stays honest rather than admiring: we are *ahead* on availability (their `when` clauses exist largely because their commands can't be dry-run) and on placement (their menu contributions are a static manifest; our cascade has sight). Egildo ruled downward over outward, on the grounds that outward is work anyone could do. Standing, with a **palette projection** as its first stone — pure, and the ranking is the part every host would get wrong.
- **The default member** · open — one-of-N surfaces raise it: is "paragraph as the domain's zero" a structural fact or a convenience? It decides whether re-pressing the current member may toggle back to a default. Until decided, one-of-N furniture is honest radio: lit when current, no-op when pressed again.
- **Focus scope** · open — the one availability guard no dry run can answer: *which surface holds the keyboard*. Editor state doesn't know whether the editor, the palette, or nothing has focus — VS Code's `when` clauses exist largely because its commands can't be dry-run, and our dry-run stone dissolves every use of them *except this one*. It also owns the outside country: a window-level summon chord (the palette's Mod-k) lives beyond the editor's keymaps entirely. The same question as the unified surface's focus handoff, seen from the keyboard's side.
- **The unified surface** · open, one joint tested (2026-07-27) — the intended surface is one hovering element that is a toolbar on a selection and morphs into a Raycast-grade command palette when summoned, all on ProseMirror commands. The confident description exists; the hard part is the focus handoff (the toolbar never takes focus; the palette must) — the focus-scope question above, seen from the surface's side. The field forced a first, narrow crossing of exactly that line and it held: a control may take focus where a button may not, because *the editor's selection is state, not focus*, and it survives the blur intact; what the surface owes back is to hand the caret over before running the command (so a node view can reclaim its own seat during the dispatch) and to stay put while engaged (the anchor, reading focus, would otherwise hide the strip the moment you clicked into it). Narrow because a field is not a palette: one control, no keyboard capture, no summon chord. The question stands; the first stone of its floor does not.
- **The top layer** · open — `popover` and the top layer are the more platform-native way to float the surface, unverified against the never-take-focus discipline.
- **Extraction** · closed (2026-07-19) — done: this repo. The trigger was the healthy one — real consumers pulling (prosemirror-spreads, the pagination plugin), not ripeness declared from inside. Fresh history by ruling; TypeScript, minimal toolchain chosen on merit (tsc + vitest, no bundler); the tablet traveled with the package. pm-testing-venue remains the proving ground, hosting this as its specimen through a `file:` dependency, its surfaces staying behind as furniture per the surfaces ruling. npm publication is a separate decision, deliberately untaken.
